# WhatsApp Web Selected-Message Exporter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Chrome + Firefox MV3 extension that exports the messages selected in WhatsApp Web's native "Select messages" mode to a ZIP (`chat.md` + `messages.json` + `media/`) for dragging into Claude Code.

**Architecture:**
- A MAIN-world content script runs bundled WA-JS plus a small read-only RPC server.
- An ISOLATED-world content script tracks the native selection, shows the Export UI, and runs the export pipeline: collect → order → write.
- The two talk over `window.postMessage`.
- All WhatsApp-specific knowledge lives in two adapters: `src/page/` (internals) and `src/dom/` (markup). Everything downstream is plain, unit-tested code.

**Tech Stack:** TypeScript, WXT 0.21.4, `@wppconnect/wa-js` 4.7.2 (exact pin), JSZip 3.10.2, Vitest 5 (+ jsdom), Playwright (live testing only), web-ext 10 (signing), pnpm, Node 26.

**Spec:** `docs/superpowers/specs/2026-10-24-wa-export-design.md`. Read it before starting any task.

## Global Constraints

- Browsers: Chrome/Chromium ≥ 111 (`minimum_chrome_version: "111"`), Firefox ≥ 128 (`strict_min_version: "128.0"`). No Safari.
- Firefox is the primary target. Every task with a build step must build for both browsers: `pnpm wxt build` and `pnpm wxt build -b firefox`.
- Firefox add-on ID, fixed from day one: `sivefunc@tuta.io`.
- Permissions: exactly `["storage"]`. Content scripts match only `https://web.whatsapp.com/*`. No `downloads`, no `host_permissions` beyond that, no remote code, no network calls from extension code.
- `@wppconnect/wa-js` pinned to exactly `4.7.2` (no `^`). It is bundled from `node_modules/@wppconnect/wa-js/dist/wppconnect-wa.js`, never fetched at runtime.
- Strictly read-only toward WhatsApp. Never send, forward, delete, react to, or mark messages read; never auto-scroll; never request media re-upload; never bypass view-once.
- Never fail silently. Every per-message or per-media failure becomes an `ExportProblem`. It shows in the UI summary, in the `chat.md` "Export problems" section, inline in `chat.md`, and in `messages.json`.
- Partial failure still produces the ZIP. A fatal error (WA-JS not ready, nothing readable, too large, cancelled) produces no ZIP and shows an error.
- For media messages the text is `caption`, never `body`.
- Size limits: warn and ask above `500 * 1024 * 1024` bytes; refuse above `1.5 * 1024 ** 3` bytes.
- Media concurrency: 3. RPC timeouts: 30 000 ms per message op, 60 000 ms per media op.
- Times are rendered in the browser's local timezone as `YYYY-MM-DD HH:mm`.
- Name in the manifest is the placeholder `WA Export for WhatsApp Web`, never starting with "WhatsApp". Don't use the WhatsApp logo.

## Review Focus

1. **Group chats.** Group message `data-id`s have four `_`-separated parts (`false_<group>@g.us_<msgId>_<participant>@c.us`). The chat JID must still parse to the group, and sender names must be the participants, not the group. Pinned in Task 4 (`parseChatJid`) and Task 3 (sender uses `author` before `from`).
2. **Media message `body` is not user text.** WhatsApp stores non-text data there for media messages, such as a base64 thumbnail. It must never reach `chat.md` or `messages.json`. Pinned in Task 3 (normalizer).
3. **Hostile or colliding attachment filenames.** Path separators, `..`, control characters, emoji, 300-character names, and two attachments both named `image.png` must become safe, unique paths under `media/`. Pinned in Task 6.
4. **Deleted, system, and unsupported messages.** Types such as `revoked`, a poll, a location, a contact card, or anything else with no text and no media must render a visible placeholder line, never an empty section or a crash. Pinned in Task 7.
5. **Selection lost or polluted.** Leaving select mode or switching chats must clear the tracked set. Rows that scroll out of the DOM must stay selected. Pinned in Task 4.

### Shared types (`src/types.ts`, created in Task 2, used everywhere)

```ts
export type MediaKind = "image" | "video" | "voice" | "audio" | "document" | "sticker";

export interface WaMediaInfo {
  kind: MediaKind;
  mime: string | null;
  filename: string | null;     // original filename, if WhatsApp has one
  size: number | null;         // bytes
  durationSec: number | null;  // voice/audio/video
}

export interface QuotedMessage {
  id: string | null;
  senderName: string | null;
  timestamp: number | null;    // unix seconds
  text: string;
}

export interface WaMessage {
  id: string;                  // the DOM data-id string, verbatim
  fromMe: boolean;
  type: string;                // raw WhatsApp type: chat, image, ptt, document, revoked, ...
  timestamp: number | null;    // unix seconds
  sender: { jid: string | null; name: string | null };
  text: string;                // caption for media messages, body otherwise; "" if none
  quoted: QuotedMessage | null;
  quotedUnavailable: boolean;  // reply to a message whose content couldn't be loaded
  media: WaMediaInfo | null;
  isViewOnce: boolean;
}

export type ProblemCode =
  | "message_not_found" | "media_not_found" | "media_expired"
  | "media_timeout" | "view_once_skipped" | "media_error";

export interface ExportProblem {
  messageId: string | null;
  code: ProblemCode;
  detail: string;              // technical detail for messages.json
}

export interface ExportedMedia {
  path: string;                // e.g. "media/002-design-spec.pdf"
  mime: string;
  filename: string | null;
  size: number;
  source: "wa-js";
}

export interface ExportRecord extends WaMessage {
  exportedMedia: ExportedMedia | null;
  problems: ExportProblem[];   // this message's problems
}

export interface ChatInfo { jid: string | null; name: string | null }

export interface ExportBundle {
  chat: ChatInfo;
  exportedAt: Date;
  records: ExportRecord[];     // already ordered
  media: Map<string, Blob>;    // path → bytes
  problems: ExportProblem[];   // every problem, including message_not_found for ids with no record
}
```

- Produces in `protocol.ts`:

```ts
export const CHANNEL = "wa-export:v1";
export interface Ops {
  HEALTH:       { req: {};                res: { ready: boolean; missing: string[]; waJsVersion: string | null } };
  GET_CHAT:     { req: { jid: string };   res: ChatInfo };
  GET_MESSAGES: { req: { ids: string[] }; res: { messages: WaMessage[]; failures: { id: string; code: "message_not_found"; detail: string }[] } };
  GET_MEDIA:    { req: { id: string };    res: { mime: string; buffer: ArrayBuffer } };
}
export type OpName = keyof Ops;
export class RpcError extends Error { constructor(public code: string, message: string) }
// Error codes used across tasks:
// "not_ready" | "media_not_found" | "media_expired" | "view_once" | "timeout" | "unknown_op" | "internal"
```

- Produces in `rpc.ts`:

```ts
export interface Transport {
  post(msg: unknown, transfer?: Transferable[]): void;
  listen(fn: (msg: unknown) => void): () => void;
}
export type Handlers = { [K in OpName]: (req: Ops[K]["req"]) => Promise<Ops[K]["res"]> };
export function createRpcServer(t: Transport, handlers: Handlers): () => void;
export interface PageRpc { call<K extends OpName>(op: K, req: Ops[K]["req"], timeoutMs: number): Promise<Ops[K]["res"]> }
export function createRpcClient(t: Transport): PageRpc;
export function windowTransport(role: "page" | "content"): Transport;
```

`windowTransport` posts `{channel: CHANNEL, dir, ...}` to `location.origin`. It accepts only messages where `event.source === window`, `event.origin === location.origin`, and `data.channel === CHANNEL` and the direction is the opposite of its own role. The server transfers `res.buffer` when present. Errors cross as `{ok:false, code, message}` and are rethrown as `RpcError` on the client.

```ts
export function mediaKindOf(type: string): MediaKind | null; // image, video, ptt→voice, audio, document, sticker; others null

export interface WppLike {                                 // the subset of window.WPP we use
  isReady?: boolean;
  version?: string;
  chat: {
    getMessageById(id: string): Promise<any>;
    downloadMedia(id: string): Promise<Blob>;
    get(jid: string): any;
  };
  contact: { get(jid: string): Promise<any> | any };
}
export const REQUIRED_FUNCTIONS = ["chat.getMessageById", "chat.downloadMedia", "chat.get", "contact.get"];
export function isExpiredMediaStage(stage: unknown): boolean;
export function createHandlers(getWpp: () => WppLike | undefined): Handlers;
```

Rules the tests pin:
- `text`: for a type with a `mediaKindOf` result, use `raw.caption ?? ""`; otherwise `raw.body ?? ""`.
- Sender JID: `author ?? from` (groups use `author`).
- Sender name: `fromMe` → `null` (the renderer prints "You"). Otherwise `resolveName(jid)`, falling back to `raw.notifyName`, then `null`.
- `durationSec` from `raw.duration` (number or numeric string).
- `media.filename` from `raw.filename`.
- `quoted`: from `raw.quotedMsg` when present. If `raw.quotedStanzaID` is set but there's no `quotedMsg`, then `quoted = null` and `quotedUnavailable = true`.
- `GET_MESSAGES`: one `getMessageById` call per ID through `Promise.allSettled`. Rejections become `failures` with code `message_not_found`. Sender names are resolved via `contact.get`, trying `name`, then `pushname`, then `shortName`.
- `GET_CHAT`: `chat.get(jid)`. Name is `formattedTitle ?? name ?? contact?.name ?? null`; the JID is echoed back.
- `GET_MEDIA`:
  - If the model has `isViewOnce`, throw `RpcError("view_once")` without calling `downloadMedia`.
  - If `isExpiredMediaStage(raw.mediaData?.mediaStage)`, throw `RpcError("media_expired")` without calling `downloadMedia`.
  - A WA-JS error whose `code` or message contains `media_not_found` becomes `RpcError("media_not_found")`.
  - Returns `{mime: blob.type || raw.mimetype || "application/octet-stream", buffer}`.
- `isExpiredMediaStage`: initial rule is true when the stage is a string matching `/ERROR|MISSING|EXPIRED|REUPLOAD|NEED_POKE/i`. Task 4's live gate confirms or corrects the list.
- `HEALTH`:
  - `ready` = `!!wpp?.isReady` and every `REQUIRED_FUNCTIONS` path is a function.
  - `missing` lists the absent ones.
  - `waJsVersion` = `wpp?.version ?? null`.
  - Every other op first awaits readiness for up to 30 000 ms (polling every 100 ms), then throws `RpcError("not_ready")`.

- Produces:

```ts
export const WARN_BYTES = 500 * 1024 * 1024;
export const MAX_BYTES = 1.5 * 1024 ** 3;
export type FatalCode = "nothing_selected" | "not_ready" | "nothing_readable" | "too_large" | "cancelled";
export interface FatalError { code: FatalCode; message: string }
export interface CollectOptions {
  ids: string[];
  rpc: PageRpc;
  orderingId: string;
  confirmLargeExport(totalBytes: number): Promise<boolean>;
  onProgress(done: number, total: number): void;   // total = messages + media items
  concurrency?: number;                             // default 3
  now?: () => Date;
}
export type CollectResult = { ok: true; bundle: ExportBundle } | { ok: false; error: FatalError };
export function collect(o: CollectOptions): Promise<CollectResult>;
```

Order of operations:
1. empty `ids` → `nothing_selected`
2. `HEALTH`; if not ready → `not_ready`
3. `GET_CHAT` with the `parseChatJid` of the first ID. A failure leaves the name `null`; it's not fatal.
4. `GET_MESSAGES` in batches of 50; zero messages → `nothing_readable`
5. `applyOrdering`
6. sum the known `media.size`: above `MAX_BYTES` → `too_large`; above `WARN_BYTES` → `confirmLargeExport`, and if declined → `cancelled`
7. `assignMediaPaths`
8. download media with a concurrency limit, mapping each failure:
   - `view_once` → `view_once_skipped`
   - `media_expired` → `media_expired`
   - `media_not_found` → `media_not_found`
   - `timeout` → `media_timeout`
   - anything else → `media_error` with the detail
9. each problem goes on its record *and* in `bundle.problems`; each `message_not_found` failure goes only in `bundle.problems`

Fatal messages (exact):
- `nothing_selected`: "Select at least one message first."
- `not_ready`: "Can't read WhatsApp's messages. The extension needs an update."
- `nothing_readable`: "None of the selected messages could be read. The extension may need an update."
- `too_large`: "This export is <X.X> GB, over the 1.5 GB limit. Select fewer large files."
- `cancelled`: "Export cancelled."
